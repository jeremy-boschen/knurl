# Knurl Documentation System

## Overview

Knurl's documentation has been unified into a single, automated system that combines AI-generated technical features with human-written tutorials and guides.

**The system has two components:**
1. **Feature Manifest** - AI-generated inventory of features
2. **Manual Content** - Human-written guides and tutorials
3. **Generated Docs** - Merged output for Astro documentation site

## Build Commands

### Quick Build (Fast)
```bash
yarn docs:create
```

Generates documentation using the **existing** feature manifest. This is the normal build:
1. Runs screenshot E2E tests to capture UI visuals
2. Regenerates feature docs from manifest (merges manual content)
3. Builds Astro documentation site

**Use for:** Regular CI/CD builds, local testing

### Full Regeneration (Slow)
```bash
yarn docs:regenerate
```

Regenerates the feature manifest **from scratch** using Ollama AI analysis:
1. Scans entire codebase for features
2. Uses Ollama to analyze and categorize features
3. Outputs updated manifest

Then manually run:
```bash
yarn docs:create
```

**Use for:** After major code changes, quarterly reviews, or when feature detection needs updating

## How It Works

### 1. Feature Manifest (AI-Generated)

The `feature-manifest.json` contains:
- All detected features from the codebase
- Feature metadata: name, description, status, confidence
- Entry points: UI routes, CLI commands, API endpoints
- Data models and configuration
- Dependencies and security info
- Evidence of where features were detected

**File:** `docs/feature-manifest/feature-manifest.json`

**Generated by:** `yarn feature-manifest` (uses Ollama qwen2.5-coder model)

**Updated:** When you run `yarn docs:regenerate` (manually, not automatically)

### 2. Manual Content (Human-Written)

Supplemental guides for each feature area:

- **Collections** - Explains what collections are, best practices
- **Authentication** - Step-by-step auth setup guides
- **HTTP Client** - Request building and response analysis tutorials
- **Core** - Request execution, variables, and environment setup
- **Getting Started** - Installation and first launch

**Files:** `docs/manual-content/{area}/*.md`

**Format:** Markdown with YAML frontmatter

**When Updated:** Edit directly when tutorials need to change

### 3. Generated Documentation (Merged)

The `generate-feature-docs.mjs` script merges AI features + manual guides:

1. Loads feature manifest
2. For each feature:
   - Gets AI-generated content (overview, why it matters, technical details)
   - Loads matching manual content (user guide)
   - Merges both into a single MDX file
3. Creates `documentation/src/content/docs/features/{area}/{feature}.mdx`

**Output:** Auto-generated MDX files (don't edit directly)

**Generated by:** `yarn generate:feature-docs` (part of `yarn docs:create`)

## Workflows

### Daily Development
```bash
# Make code changes
git add .
git commit -m "feat: add new feature"

# Build docs with current manifest
yarn docs:create
```

### After Major Feature Work
```bash
# After significant code changes
yarn docs:regenerate  # Regenerate manifest with Ollama
# Wait for Ollama analysis...
yarn docs:create      # Build docs from updated manifest
```

### Updating Documentation

**To update a guide:** Edit `docs/manual-content/{area}/*.md`

```bash
# Example: Update authentication guide
vi docs/manual-content/auth/authentication-setup.md

# Rebuild docs (manifest stays the same)
yarn docs:create
```

**To add a new tutorial:**

1. Create new file in `docs/manual-content/{area}/`
2. Add YAML frontmatter with metadata
3. Write content in markdown
4. Run `yarn docs:create` - it will be included if matching area

### Quarterly Manifest Review
```bash
# Run full AI analysis of codebase
yarn docs:regenerate

# Review changes
git diff docs/feature-manifest/feature-manifest.json

# Commit if satisfied
git add docs/feature-manifest/
git commit -m "chore: update feature manifest from code analysis"

# Build docs
yarn docs:create
```

## Manual Content Format

### Frontmatter Example
```yaml
---
title: "Setting Up Authentication"
description: "Step-by-step guide to configure authentication methods"
category: "auth"
relatedFeatures:
  - auth.request-authentication
  - auth.oauth-flows
order: 10
---
```

### Fields
- **title** - Display name
- **description** - Short description
- **category** - Area slug (auth, collections, http-client, core)
- **relatedFeatures** - Feature IDs this guide relates to (optional)
- **order** - Sort order within area (optional)

## Understanding the Build Pipeline

### `yarn docs:create` (Regular Build)
```
1. Run screenshot E2E test
   └─ Captures UI screenshots for docs
2. Generate feature docs
   └─ Loads existing manifest
   └─ Merges with manual content
   └─ Creates MDX files in documentation/src/content/docs/features/
3. Build Astro site
   └─ Reads features from MDX files
   └─ Generates HTML documentation site
   └─ Output in documentation/dist/
```

### `yarn docs:regenerate` (Full Regeneration)
```
1. Run Ollama feature detection
   └─ Analyzes entire codebase
   └─ Extracts routes, endpoints, data models
   └─ Generates new feature-manifest.json
2. Saves manifest for version control
   └─ Commit changes for reproducibility
```

## Important Notes

### ✅ Version Control

**DO commit:**
- `docs/feature-manifest/feature-manifest.json` - Ensures reproducible docs
- `docs/manual-content/` - Human-written guides
- Changes to `scripts/generate-feature-docs.mjs`

**DO NOT commit:**
- `documentation/src/content/docs/features/` - Auto-generated, recreated each build
- `documentation/dist/` - Build output

### ⚠️ Do NOT Edit Generated Docs

The files in `documentation/src/content/docs/features/` are auto-generated. Edit them directly and your changes will be lost on the next build.

**To update feature docs:** Edit `docs/manual-content/` instead.

### 🚀 CI/CD Integration

In CI/CD pipelines:
```bash
# Fast build - uses committed manifest
yarn docs:create
```

**Not** `yarn docs:regenerate` (unless you have Ollama available).

### 🔄 Ollama Requirements

For `yarn docs:regenerate`, you need:
- Ollama running locally
- `qwen2.5-coder:7b` model installed
- 7GB+ memory available

See `OLLAMA_SETUP.md` for detailed setup instructions.

- ✅ Removed old auto-docs E2E test system
- ✅ Consolidated manual docs into supplemental content

- **Single Source of Truth** - One merged doc per feature

- **Automated** - Build process handles merging
- **Reproducible** - Manifest in git for exact versions

## Troubleshooting

### Docs build fails
```bash
# Check for syntax errors
yarn generate:feature-docs

# Verify Astro can build
cd documentation && astro build
```

### Feature manifest outdated
```bash
# Regenerate from scratch (requires Ollama)
yarn docs:regenerate

# Or just use existing manifest
yarn docs:create
```

### Missing screenshots
```bash
# Regenerate screenshots
npm run test:e2e -- --spec=documentation/e2e/screenshots.e2e.ts

# Then build docs
yarn docs:create
```

### Manual content not appearing
1. Check file is in correct directory: `docs/manual-content/{area}/*.md`
2. Check YAML frontmatter is valid
3. Verify category matches area slug
4. Run `yarn generate:feature-docs` with verbose logging
