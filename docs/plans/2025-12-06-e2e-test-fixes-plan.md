# E2E Test Fixes Plan - 2025-12-06

## Root Cause Analysis

The 21 failing E2E tests fail because **test data-test-id references don't match actual app component IDs**. Tests were written expecting certain IDs that don't exist in the actual UX reference page or request editor components.

### Key Findings from Code Audit

1. **UX Reference Page** (`src-ui/src/pages/e2e-ux-reference.tsx`) has been recently updated with proper data-test-ids
2. **Tests** (`src-common/e2e/specs/settings-ui.e2e.ts` and `src-common/e2e/specs/ux-reference.e2e.ts`) reference outdated test IDs
3. **Actual vs Expected IDs:**
   - Tests expect: `ux-reference:select-open-state` → Actual: `ux-reference:select-value`
   - Tests expect: `ux-reference:menu-trigger` → Actual: `ux-reference:dropdown-trigger`
   - Tests expect: `ux-reference:button` → Actual: `ux-reference:button-primary`, `button-secondary`, etc.
   - Tests expect: `ux-reference:dropdown-item:*` → Component ID exists but selector is failing

## Critical Insight: Radix UI Portal Issue

The primary blocker is **Radix UI SelectContent, DropdownMenuContent, and other portal components render outside the normal DOM flow**. WebDriver queries may not find these elements immediately because:

1. Portal content renders asynchronously
2. Elements render in a separate DOM container (usually at document.body level)
3. Standard `waitForExist()` may timeout before portal renders

**Solution:** Update `selectOptionByTestId()` helper to:
```typescript
1. Click trigger element
2. Wait for portal content with extended timeout (5-10s)
3. Query portal container for option element
4. Wait for option to be displayed
5. Click option
```
